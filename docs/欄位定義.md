# 用戶 / 非用戶 欄位定義

> 核心原則：**非用戶不是「資料很少的人」，是「資料不會更新的人」。**
> 掃名片該有的欄位一個都不少，差別在**保鮮**與**深度**。

## 一、共通欄位（掃名片就會有，兩種人都有）

| 欄位 | 來源 | 備註 |
|---|---|---|
| 姓名 / 英文名 | OCR | |
| 職稱 | OCR | |
| 部門 | OCR | |
| 公司 | OCR | 公司情報區的 key |
| 手機 | OCR | 可直接撥號 |
| 公司電話 | OCR | 可直接撥號 |
| Email | OCR | 非用戶的唯一聯絡管道 |
| 公司網址 | OCR | 可開啟 |
| 地址 | OCR | |

## 二、用戶專屬（只有 Heycard 用戶才有）

| 欄位 | 為什麼非用戶沒有 |
|---|---|
| 即時名片 | 需要本人維護 |
| 多重身分 | 需要本人建立 |
| 一句話介紹 | 名片上通常沒有 |
| 可提供 / 正在找 | **合作判斷的燃料**，名片印不出來 |
| 他發的貼文 | 需要帳號 |
| 公開頁 | 需要帳號 |
| 自動更新 | 需要本人同步 |

## 三、你自己的（系統不得覆蓋）

備註 · 認識時間 · 場域 · 你給他哪張卡 · 收錄方式

> 合併時這一層**永遠保留**，只更新第一、二層。
> 依據資料倫理鐵則：你在場的事可以講，你不在場的事不要講。

## 四、UI 差異

| | 用戶 | 非用戶 |
|---|---|---|
| 身分區 | 真名片（本人維護） | 字首磚 ＋「名片掃描 · 不會自動更新」 |
| 頭像 | 本人上傳 | **一定沒有** → 材質字首磚 |
| 主行動 | 傳訊息（站內） | 寄信（Email） |
| AI 擬稿 | 站內草稿 | **自動改道寄信畫面** |
| 公開內容 | 他的貼文、offer/want | 無 |
| 頁尾 | 無 | 「他加入之後，你會多拿到」＋ 寫封信給他 |

## 五、寄信邏輯

```
非用戶 → 沒有站內訊息 → 一律走寄信
  · 主行動「寄信」
  · 任何 AI 擬稿（data-draft）自動攔截改道到 mail 畫面
  · 信末可附 Heycard 署名與邀請連結（可關）
  · mailto: 預填 收件人／主旨／內文（三者都會帶入，不必重打）
    限制：無附件、無 HTML、URL 上限約 2000 字
    正式版建議改系統代寄，才能附名片預覽圖與追蹤點擊
```

## 六、合併（非用戶 → 用戶）

新資料為主、舊資料併入：
- 第一、二層欄位以**新值覆蓋**，畫面用刪除線對照新舊
- 第三層（你記的）**完全保留**，不進入 diff
